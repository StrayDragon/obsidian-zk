## Why

目前插件的用户可见文案已经统一为“中文（English token）”的双语提示，但随着功能增长，文案分散在各处会再次出现不一致（例如 inbox/收件箱/收集箱）。需要一个轻量的 i18n/文案注册表作为单一事实来源，让同一概念在命令、操作面板、设置、提示等所有 UI 中永远一致，同时又不引入多语言维护成本（仅提供中文文案，文案内保留 English token）。

## What Changes

- 引入轻量 i18n 层（只提供中文文案）：提供 `t(key, params?)` 作为所有用户可见文案的唯一出口，并支持基础插值。
- 建立 `zh` 文案字典与稳定的 key 命名规范，覆盖命令、设置、Modal/View、Notice、统计/筛选等所有用户触达的文案。
- 将现有分散字符串逐步迁移到 i18n 字典中，保留并强化“中文（token）/中文（zk_key）”的概念映射写法。
- 增加最小化的校验/约束（类型与简单检查），避免遗漏 key 或在 UI 中继续出现硬编码文案。

## Capabilities

### New Capabilities
- `ui-i18n`: 为插件提供仅中文的 i18n 文案基础设施（key → 文案），用于统一并稳定所有用户可见文案输出。

### Modified Capabilities
- `ui-copy-consistency`: 增加“所有用户可见文案必须经由 i18n 输出”的要求，以降低未来文案漂移风险。

## Impact

- 代码影响：会触及 `src/` 下的命令、设置与 UI 组件，把字符串收敛到 i18n 字典与少量 helper；不引入大型依赖，保持 bundle 体积可控。
- 行为影响：对用户可见行为不变（文案内容原则上保持一致），但可减少未来新增功能时的文案不一致问题。
- 维护影响：后续修改术语只需改字典一处；为将来真正多语言提供扩展点（本变更不提供语言切换 UI）。
